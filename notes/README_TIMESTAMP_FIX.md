# PersTSFM Phase 3.3C — Timestamp-unit fix

The original export and cadence code assumed `DatetimeIndex.asi8` returns nanoseconds. On microsecond-resolution timestamps it returns microseconds, so older snapshot archives contain incorrectly labeled `timestamps_ns` values, and `cadence_minutes` falsely reports irregular chronology.

The patched script uses canonical nanosecond values in SHA256, input checking, snapshot serialization and cadence checking. Snapshots now carry `snapshot_schema=pertsfm_3_3c_history_ns_v2` and `timestamp_unit=ns`; old unversioned snapshots are intentionally rejected.

## Apply

From your repository root, use `unzip -o` (not `-n`) to replace the two code files. Back them up first if desired.

```
cp scripts/phase3/context_saturation.py scripts/phase3/context_saturation.py.before_timestamp_fix.bak
unzip -o PersTSFM_phase3_3c_timestamp_fix.zip
conda activate PERTSFM_ENV
python -m pytest -q tests/phase3/test_context_saturation.py
```

## Re-export pre-official snapshot (required)

Do not reuse `mdense_preofficial_full.npz` generated by the original script, even though its old SHA256 passed. That snapshot silently encoded microsecond timestamps as nanoseconds.

```
conda activate PERTSFM_DATA_ENV
python scripts/phase3/context_saturation.py --task M_DENSE_1H --export-snapshot results/phase3/context_saturation_inputs/mdense_preofficial_full_ns_v2.npz
conda activate PERTSFM_ENV
python scripts/phase3/context_saturation.py --task M_DENSE_1H --snapshot results/phase3/context_saturation_inputs/mdense_preofficial_full_ns_v2.npz --max-entities 4 --contexts 768 3072 8192 --batch-size 4 --execute
```

Never overwrite old frozen experiment results; the old snapshot may be kept as a provenance record, clearly labeled invalid for forecast work. The new snapshot is compatible with the new script only.
